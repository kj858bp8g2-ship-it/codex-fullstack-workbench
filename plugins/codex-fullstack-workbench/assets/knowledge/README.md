# 项目知识复利目录

这个目录只保存经过筛选、能帮助后续任务的项目知识，不保存完整聊天记录。

## 文件职责

- `inbox.md`：新发现的候选经验，必须附来源和验证证据。
- `playbook.md`：经过重复验证、当前仍有效的规则与工作流。
- `retired.md`：已失效、被替代或不再推荐的经验，并记录淘汰原因。

## 复利循环

1. 捕获：记录一次高信号发现、失败根因或有效工作流。
2. 提炼：去掉项目私密信息和偶然细节，明确适用条件与不适用条件。
3. 验证：用真实任务、测试、Diff 或可复现结果确认，不以模型自评代替证据。
4. 晋升：项目规则进入 `AGENTS.md`，操作方法进入 `playbook.md`，稳定跨项目流程再创建 Skill。
5. 复用：记录后续使用结果；没有改善的技巧不继续提高权重。
6. 淘汰：依赖、架构或官方行为变化后重新验证；失效内容移入 `retired.md`。

## 晋升门槛

- 单次观察默认只进入 `inbox.md`。
- 至少两次独立成功，或一次高风险问题且有强验证证据，才进入候选 Playbook。
- 创建 Skill 前至少准备两个真实用例、明确触发条件、失败边界和验证方式。
- 只有在多个项目独立验证后，才考虑晋升为用户级 Skill 或个人插件；该全局写入必须单独确认。
- 连接账号、实时数据或外部动作的能力应进入插件/MCP，而不是伪装成静态知识。

## 安全边界

不得记录密钥、Token、Cookie、客户数据、内部账号、个人绝对路径或可识别的私有日志。对外分享或晋升为公共 Skill 前必须再次脱敏和检查许可证。
