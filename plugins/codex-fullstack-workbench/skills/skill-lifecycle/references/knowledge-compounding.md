# 知识与技巧复利

知识复利不是保存全部聊天，而是把高信号经验逐步晋升为更稳定的载体。

## 捕获什么

- 重复出现的错误根因和容易遗漏的前置条件。
- 明显改善结果的提示结构、检查清单或工具顺序。
- 真实验证过的命令、平台差异、回滚与恢复方法。
- 用户反复纠正的项目事实、边界和审查意见。

不要记录普通常识、一次性路径、未经验证的猜测、冗长日志、密钥、客户数据或完整聊天。

## 六步循环

1. **捕获**：写入 `.codex-workbench/knowledge/inbox.md`，附适用范围、证据和不适用条件。
2. **提炼**：去掉偶然细节，判断它是项目事实、规则、工作流还是外部能力。
3. **验证**：至少在第二个独立任务中复用；高风险问题可以用一次强证据进入候选，但仍需审查。
4. **晋升**：
   - 项目事实与当前结构 → 项目上下文文档；
   - 每次都必须遵守的短规则 → 最近的 `AGENTS.md`；
   - 已验证但仍需人工判断的技巧 → `playbook.md`；
   - 稳定、重复、包含非显然步骤的跨任务流程 → 项目级 Skill；
   - 在多个项目独立验证的个人方法 → 经确认后进入用户级 Skill 或个人插件；
   - 需要实时数据、登录或外部动作 → 插件/MCP。
5. **复用**：记录成功、失败和验证差异；没有真实增益的内容降低权重。
6. **淘汰**：依赖、架构或官方行为变化后复查；失效条目移入 `retired.md`，避免继续加载。

## 自动化能做什么

每周定时任务可以聚类候选、查重复、检查过期来源并生成晋升建议。默认不得自动改写用户编辑过的 `AGENTS.md`、Playbook 或 Skills；同一知识发生冲突时保留双方证据，交给用户裁决。

## 与现有能力配合

- 有 `capture`、`recall`、`distill` 等知识工具时，可以处理采集和聚类，但最终晋升门槛不变。
- 需要新 Skill 时转到 `skill-creator`，并保留真实用例、验证和来源。
- 项目内先验证，再考虑跨项目晋升；写入用户级目录或个人 Marketplace 属于全局变更，必须单独确认。
- 需要寻找现成能力时先用 `find-skills`；不要把已有成熟能力重新发明一遍。
- 详细知识文件按需读取，不把完整历史塞入每个任务，避免消耗 Context Headroom。
