# 每周更新维护

目标不是追新，而是让 Workbench、项目 Skills 和插件来源保持可追踪、可验证、可回滚。

## 默认模式：自动审计，不静默覆盖

每周任务读取插件根目录 `assets/maintenance-policy.json`；项目级安装时同时读取 `.codex-workbench/maintenance-policy.json` 和 `source-registry.json`。Registry 中没有真实来源、Revision 或信任审查的条目保持只报告。默认完成：

1. 只检查已登记或能够追踪到可信来源的 Workbench、Skills 和插件市场。
2. 将远程候选下载到临时目录，不直接修改当前有效文件。
3. 阅读 Release Notes，并对 `SKILL.md`、脚本、Hook、MCP、网络、认证和权限变化做 Diff。
4. 运行候选自带验证器和一个无敏感数据的代表性 smoke test。
5. 按低、中、高风险分类，输出更新建议和回滚方法。
6. 来源不明、许可证变化、验证失败或新增高风险能力时，只报告，不安装。

“插件市场已刷新”“插件已更新”“账号已重新授权”是三种状态。官方 CLI 支持刷新已配置的 Marketplace，但刷新全局来源仍是写操作；只有用户明确启用时才执行。不得假设所有插件都有统一的静默更新命令。

## 可选模式：隔离暂存可信更新

用户明确选择 `stage-trusted-updates` 后：

- Git 项目在独立 Worktree 中暂存项目级 Workbench 更新，保留 Diff，不合并到主工作区。
- 非 Git 项目退回只读审计，不能用“已备份”代替隔离。
- 用户级 Skills、插件、Marketplace、外部账号和全局配置仍只报告。
- 新脚本、新网络访问、Hook、MCP、认证、全局写入和权限扩大永不自动晋升。

## Scheduled 任务边界

- 本地定时任务适合使用 Codex 桌面应用；电脑、应用和项目路径在运行时间必须可用。
- 第一次先在普通任务中手动运行相同提示词，检查范围和输出。
- 使用最小沙箱与网络范围；后台任务无人值守，不能依赖临时确认。
- 任务应独立输出更新收件箱；只有需要持续上下文时才绑定到同一任务。
- 前几次运行必须人工复核，频繁 Worktree 需要定期清理。

## 报告格式

每个候选输出：来源、当前版本或 Revision、候选版本、主要 Diff、脚本与权限变化、验证结果、风险等级、建议动作和回滚方式。没有可信来源的条目放入“来源待登记”，不要猜测上游。
