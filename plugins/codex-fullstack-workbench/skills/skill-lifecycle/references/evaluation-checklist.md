# Skill 评估与生命周期清单

## 先决定是否需要 Skill

| 情况 | 建议 |
| --- | --- |
| 一次性的常规任务 | 直接使用 Codex，不新增依赖 |
| 重复任务，已有可信且贴合的 Skill | 审查后优先复用 |
| 组织专有规则、固定 Schema 或脆弱顺序 | 创建项目级 Skill |
| 需要连接账号、API 或远程数据 | 先判断应该使用插件/MCP，而不是纯 Skill |
| 只因“以后可能用到” | 记录候选，不默认安装 |

## 候选评估

1. 任务匹配：解决的是具体缺口，还是只重复通用提示词？
2. 来源与许可证：作者、仓库、版本、许可证和最近维护状态是否清楚？
3. 内容审查：完整读取 `SKILL.md`；检查脚本、网络调用、安装命令和外部下载。
4. 权限与数据：是否读取主目录、Secrets、浏览器登录态或客户资料？是否包含写入、发送、部署或删除？
5. Context 成本：描述是否准确，主体是否精简，引用是否按需加载？
6. 重叠关系：当前是否已有同类 Skill？触发描述会不会互相争抢？
7. 验证能力：能否用隔离样例证明真实增量？失败和卸载路径是否明确？

安装量与 Stars 可以帮助排序，但低使用量不自动等于低价值，高使用量也不证明安全或适合当前项目。

## 安装后验证

- 新任务中能发现 Skill。
- 自然语言与显式名称都能在预期场景触发。
- 一个真实小任务的输出优于未安装时，且没有越过权限边界。
- 记录来源、版本、安装范围、验证命令和卸载方式。

## 创建检查

- 至少有两个具体使用例子和清楚的触发语句。
- 已选择合适自由度：文本指引、带参数脚本或严格确定性脚本。
- `name`、目录和触发描述一致。
- 没有 TODO、个人路径、Secrets 或多余文档。
- `agents/openai.yaml` 与 Skill 内容一致。
- 官方快速验证通过，并在真实任务上前向验证。

## 维护

- 更新前先看 Diff、版本说明、权限变化和新增脚本。
- 更新后重新验证代表性任务。
- 每周自动任务默认只检查、验证和报告；项目级可信候选也应先在隔离 Worktree 暂存。
- Marketplace 刷新、插件安装、插件认证和 Skill 文件替换分开记录，不把其中一个成功当成全部完成。
- 为每个第三方能力保留来源、版本或 Revision、安装范围、验证和回滚方式；来源丢失时停止自动更新。
- 长期不触发但仍承担关键恢复、安全或迁移能力的 Skill 可以保留。
- 功能完全重叠、来源失效或长期无法验证的 Skill 应禁用或移除，并保留可恢复记录。

## 知识晋升

- 单次观察只进入 Inbox，不直接写入 `AGENTS.md` 或 Skill。
- 晋升前记录适用范围、不适用条件、至少两个真实用例或一次高风险强证据。
- 项目事实、短规则、Playbook、Skill 和插件/MCP 分别承担不同层级，不把所有内容都塞进 `AGENTS.md`。
- 提炼时删除密钥、客户数据、个人路径、私有日志和来源不明内容。
- 依赖、架构或官方行为变化后重新验证；失效内容进入淘汰记录，不继续加载。
