# Database and Auth

将数据正确性和授权边界视为同一个系统问题。任何迁移、批量更新或权限扩大都需要明确确认。

## 工作流

1. 识别数据所有者、敏感级别、租户边界、基数与生命周期。
2. 建模约束、唯一性、引用关系、时间语义和删除策略。
3. 检查查询计划、索引、分页、N+1、锁和事务边界。
4. 将认证、角色、资源级授权和数据库策略逐层对应。
5. 为迁移设计向前、回填、兼容窗口、回滚或可恢复方案。
6. 在隔离环境验证，并按 [references/data-auth-checklist.md](references/data-auth-checklist.md) 审查。

## 不可越过的边界

- 不在未经确认的数据库运行迁移或数据修复。
- 不将服务端密钥、连接串或用户凭据写进仓库或日志。
- 不把客户端隐藏按钮当作授权。
- 不用删除未知角色或数据来“简化”显示；先暴露未知状态供审查。

## 输出

给出 Schema/查询/策略变化、迁移阶段、数据风险、授权矩阵、验证环境与回滚条件。
