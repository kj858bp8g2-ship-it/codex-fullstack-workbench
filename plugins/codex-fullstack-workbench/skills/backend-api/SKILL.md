# Backend and API

从调用方可观察的契约开始，而不是从框架文件开始。

## 工作流

1. 定义调用方、身份、输入、输出、错误、超时和重试语义。
2. 明确验证、授权、租户与数据边界；认证成功不代表有权执行操作。
3. 将传输层、业务规则和持久化边界分开，但不为简单逻辑制造抽象。
4. 为重复请求、并发、部分失败和外部服务不可用设计行为。
5. 使用结构化错误与稳定状态码；日志中保留关联标识，不记录秘密或敏感正文。
6. 优先添加契约或服务级回归测试，再做实现。
7. 按 [references/api-checklist.md](references/api-checklist.md) 验证兼容性与运行特性。

## 停止条件

- 公开契约变化没有版本或兼容方案。
- 写操作的权限、幂等或审计要求不明确。
- 任务需要真实外部调用、生产数据或付费操作但未获授权。

## 输出

报告契约变化、授权规则、失败语义、测试证据、可观测性和未验证的外部依赖。
