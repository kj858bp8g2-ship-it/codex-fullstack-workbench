# 代码库索引：CodeGraph 与 Codebase Memory

先用 `rg`、语言服务和项目现有测试回答局部问题。只有问题需要跨多层依赖追踪、架构回溯、长期交接或多轮复用时，才启用代码库索引。

## 选择一个主索引

| 情形 | 首选 | 原因 |
| --- | --- | --- |
| 当前任务要快速追踪调用链、依赖关系或跨文件实现 | CodeGraph | 适合从一个问题出发做图式探索；先限定问题和目录，避免泛扫。 |
| 长期维护的大仓库，需要跨任务保存索引、检索架构或检测变更 | Codebase Memory | 适合先索引授权仓库，再用架构、图搜索、路径追踪和变更检测复用结果。 |
| 小仓库、单文件 Bug、已经能被搜索和语言工具回答的问题 | 不启用 | 索引成本和陈旧结果没有实际增益。 |

同一任务先选一个主索引。只有主索引命中不足、结果过时或确实缺少另一类能力时，才切换或补充另一个；不要为了展示配置同时查询两套图。

## 使用顺序

1. 先确认当前项目根目录、Git 状态、授权范围和目标问题。
2. 用 `rg` 找到入口、关键词和相邻测试，形成一个可检验的问题。
3. 需要图关系时调用选定索引，并把查询限定为模块、符号、调用链或架构问题。
4. 回到真实文件、测试和浏览器验证结论；索引结果是导航和假设，不是事实替代品。
5. 对长期项目，变更较大或索引明显陈旧时先更新/检测索引；不要把完整聊天、客户数据或私有日志写进索引知识。

## 最小验证

- CodeGraph：确认它能返回与当前仓库和问题相关的节点/关系，再抽查至少一个真实文件路径。
- Codebase Memory：确认项目已按当前仓库路径建立索引；用架构、图搜索或路径追踪得到的结果抽查真实文件；代码变动后检查是否需要变更检测或重建。
- 两者都不可用时直接回退到 `rg`、语言工具和分段阅读，不安装、不认证、不改全局配置。

## 用户可直接这样说

```text
先用 rg 定位入口。这个问题涉及跨文件调用链时，再按需使用当前可用的 CodeGraph 或 Codebase Memory；只选一个主索引，结果必须回到真实文件和测试验证。不要安装新 MCP、不要上传代码、不要修改全局配置。
```
