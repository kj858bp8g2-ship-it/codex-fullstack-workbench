# Testing and Debugging

先证明失败，再修改；先解释根因，再扩大验证。

## 工作流

1. 记录实际现象、环境、输入、期望行为和最小复现命令。
2. 从服务状态、端口、版本、配置和依赖等廉价事实开始排查。
3. 将假设按可能性和验证成本排序，每次只改变一个变量。
4. 创建最小回归检查，使其在修复前失败、修复后通过。
5. 实施最小修复，不以无关重构掩盖根因。
6. 运行目标测试，再按影响面扩大到类型、Lint、构建、集成或浏览器验证。
7. 使用 [references/debug-record.md](references/debug-record.md) 记录证据与未验证项。

## 约束

- 不把重新启动后暂时消失当作根因解决。
- 不随意删除缓存、锁文件、数据库或用户配置。
- 不修改测试来迎合错误实现，除非契约本身经确认改变。
- 受控样本、本地 Fixture 和模拟结果不能描述成生产证据。

## 输出

给出复现、根因、改动、RED→GREEN 证据、回归范围和剩余风险。
