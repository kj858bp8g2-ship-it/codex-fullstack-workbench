# Frontend Quality

正确只是底线。界面还要有清楚的信息层级、一致的视觉语言、可靠状态和真实设备上的可用性。

## 工作流

1. 读取现有设计系统、相邻页面、组件库和品牌约束，优先复用。
2. 在编码前确定一个具体视觉方向：受众、气质、字体、色彩、密度与关键识别点。
3. 先完成内容层级与布局，再处理组件细节和动效。
4. 实现 loading、empty、error、disabled、focus、hover 和长内容状态。
5. 在常见宽度验证响应式、键盘、对比度、语义结构和减少动效偏好。
6. 使用真实浏览器或截图审查视觉结果；不要仅凭代码断言“好看”。
7. 按 [references/visual-review.md](references/visual-review.md) 做最终审查。

## 审美约束

- 避免无意义的渐变、玻璃拟态、巨型标题、漂浮卡片和均匀堆叠的模板感。
- 一个页面只保留少数主色、字号层级、圆角和阴影规则。
- 用间距、尺度、对齐和留白建立层级，不靠到处加边框。
- 动效只解释状态变化或空间关系，并支持 `prefers-reduced-motion`。
- 未提供品牌资产时使用可替换的占位内容，不伪造 Logo 或客户素材。

## 输出

说明视觉方向、复用项、实现范围、浏览器/视口验证、可访问性结果和仍需设计确认的地方。
