# Context Headroom 操作手册

## 读取策略

- 先文件名，再命中行，再相邻上下文，最后才读整文件。
- 优先当前任务入口、调用方、测试、类型和配置。
- 大文件先看目录、标题、帮助或结构；不要默认全量加载。
- 工具支持并行时，可并行执行互不依赖的只读检查。

## 输出策略

- 工具输出只保留结论、关键片段和可复现命令。
- 不重复已经确认的背景；引用当前状态摘要。
- 详细规范放在 `references/`，主 Skill 保留决策流程。

## 阶段摘要模板

```text
目标与范围：
基线/工作目录：
已完成：
当前证据：
已验证：
未验证：
风险/阻塞：
下一唯一动作：
```

## 可选配置

插件的 `assets/config.headroom.example.toml` 展示 `tool_output_token_limit`、`model_context_window`、`model_auto_compact_token_limit` 与作用域字段。它是需要人工合并的示例，不是安装脚本：

- 先用 `/status` 确认当前模型、上下文容量和剩余空间。
- `tool_output_token_limit` 过低会截掉构建或测试的关键尾部，修改后应做真实长输出验证。
- 模型上下文与自动压缩阈值默认使用模型目录值；只有明确了解当前模型时才覆盖。
- 压缩前先写阶段摘要，避免把工作目录、未提交改动、失败证据或下一动作压掉。

## 何时拆分

只有子任务边界清晰、可独立验证且不会争抢同一文件时才并行。不要为了形式拆分，也不要用子任务代替主任务的最终整合和审查。
