# Context Headroom

目标不是让回答最短，而是把上下文留给决策、实现、验证和审查。

## 工作流

1. 定义当前切片：目标、范围、已知事实、开放问题、停止条件。
2. 使用 `rg --files`、定向搜索、行范围和入口文件，避免无目的全量读取。
3. 先读 Skill 元数据与主流程；只有任务触发时才读取 `references/`。
4. 对长日志只保留错误上下文、首个根因和最终摘要；将原命令记下来即可。
5. 在探索、实现、验证和交接边界更新短状态，不反复粘贴历史。
6. 使用可用的 `/status` 观察上下文；接近上限时先生成续接摘要，再考虑 `/compact`。
7. 按 [references/headroom-playbook.md](references/headroom-playbook.md) 判断何时分任务、压缩或停止扩大范围。

## 不应省略的内容

- 用户目标、显式边界和待确认决策
- 适用 `AGENTS.md` 与安全约束
- 真实失败证据、关键 Diff 和验证结果
- 工作目录、分支、未提交改动与下一条精确命令

## 输出

必要时输出一份续接摘要：基线、已完成、当前问题、证据、未验证、风险和唯一下一步。
