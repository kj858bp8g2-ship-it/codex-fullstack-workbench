# Project Onboard

目标是找到完成当前任务所需的最小事实集，不是把整个仓库读进上下文。

## 工作流

1. 确认工作目录、Git 状态和用户要求的范围。
2. 从根到目标文件读取适用的 `AGENTS.md`，再读 README、清单与脚本。
3. 使用文件清单和定向搜索定位入口、相邻实现、测试与配置；避免先做全仓库逐文件阅读。
4. 运行最小只读命令确认运行时、版本和现有行为。
5. 读取 [references/repository-map.md](references/repository-map.md)，输出一页式仓库地图。
6. 在修改前列出已知事实、待确认假设、成功标准和最小验证命令。

## 停止条件

- 工作目录或目标仓库不明确。
- 存在会被覆盖的用户改动。
- 需求涉及权限、数据迁移、公开接口或部署，但授权边界未确认。

## 输出

只报告与当前任务相关的技术栈、入口、数据流、约束、命令、风险和下一步。将推断明确标记为推断。
